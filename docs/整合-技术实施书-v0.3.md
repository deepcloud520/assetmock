# 整合技术实施书 v0.3

## 工程与来源
assetmock 为交付仓库；Next 16.4.2、React19、Node22、npm锁文件。导入 Financial Associates main 对应代码树及用户指定的本地未提交模拟交易代码。文件来源及SHA256见 import-financial-associate.json；原目录、数据库、密钥均不迁移。

现有游戏领域模块独立于产品，保留整数分、decimal.js和确定性引擎。游戏CSS通过 @scope (.life-game) 限定作用域。首页挂载完整产品工作区；PlanningHub 场景页挂载 IntegratedSimulation。

## 存储与接口
产品数据使用 Prisma SQLite；游戏继续使用 better-sqlite3 SQLite。新增 SimulationOpening 保存用户确认的简化输入，SimulationReport 保存工作区、会话、目标、来源快照、版本和报告索引。

/api/simulations 提供 opening、catalog、plans、runs、reports 子路由。新局归属为工作区+匿名会话，推进保持版本比较和幂等事务。报告按runId及version幂等保存；不能输入客户端余额。公开接口不返回随机记录。旧 /api/v2 与早期接口保持旧会话和规则。

金额跨模块为非负整数分字符串；确认时限制单字段最多10¹²分（100亿元），给360个月累计计算保留安全整数空间。租金不大于生活费，非零既有负债要求正月还本金。预算来源去掉元数据后校验，按已接受消费调整、保费包含标识与债务包含标识计算；未知输入不默认已确认。

来源摘要覆盖当前资产、负债、目标、预算、约束与预留。确认时重新核对摘要；快照冻结后允许继续旧局，报告列表提示来源更新。新规则版本0.3.0；旧局不重写。规划A/B/C方案不直接映射成游戏付款方案。

报告创建与游戏推进分离，不进行跨库财务写入。永久清除相关业务资料时，同时清除本工作区新推演快照、报告、游戏和AI缓存。原浏览器存档通过只读入口查阅。产品备份保留原功能；整套两库备份／恢复使用停服务后的 backup:all 命令并验证哈希。

## AI与后台
统一模型配置按模块显式字段优先，OPENAI_*与LLM_*互相回退；视觉模型独立。游戏沿用真实搜索与资料来源校验，新增可接受经过确认的自定义底账快照。生成金额仍来自计算工具。

dev:all/start:all 管理Web、撮合worker、策略worker，退出或子进程停止时终止其他子进程。实时策略worker只处理LIVE账户。合成演示使用现有REPLAY时钟；AI账户可手动运行当前回放时点，再推进K线撮合，读取范围不包含未来价格。两类账户仍需策略确认与授权。实时资料门槛不放宽。

## 验证
npm test 自动生成临时迁移数据库，按模拟交易、游戏与统一底账、其余业务、迁移脚本分组；组超时180秒则失败，不能把停滞当成通过。Playwright使用独立3100端口、.next-e2e目录和测试数据库。真实模型验证独立记录。验证详情见本次验收记录。
