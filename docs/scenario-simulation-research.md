# 情景模拟玩法调研与 AI 资产管家改版建议

调研日期：2026-09-28  
范围：初始属性确定后，通过点击或自动播放推进时间、观察事件与人物命运的文字模拟玩法。本文研究共同机制，不做竞品优劣比较。文中“观察”来自游戏作者页面或开源实现；“建议”是针对本产品的设计推导。

## 一、结论

用户期待的体验可以概括为：**用真实财务画像开局，点击“下一年”看到一段有因果的人生故事；每段故事都改变财务状态，最终回看目标如何达成、推迟或失守。**

现有功能已能做一次重大事件的财务计算，但交互主角是“先填冲击参数，再逐期看数字”。改版应把主角改为“人物在时间中经历事件”，计算器留在故事背后，结果仍可展开核对。建议产品命名为“财务人生推演”，与现有“压力测试”区分入口或模式。这里的“人生”指财务相关的人生节点，不宣称预测一个人的真实命运。

## 二、这一类玩法的共同骨架

### 1. 开局：少量属性决定“这个人可能遇到什么”

《人生重开模拟器》的开源实现有初始属性、天赋、事件记录和成就记录；每推进一次年龄，程序先触发天赋，再从该年龄的候选事件中筛选并抽取事件。[原版项目](https://github.com/VickScarlet/remake)、[推进规则源码](https://github.com/VickScarlet/remake/blob/main/packages/core/src/game.ts)、[状态结构源码](https://github.com/VickScarlet/remake/blob/main/packages/core/src/state.ts)

这说明初始属性的作用不是做一张静态档案，而是持续影响事件资格、结果和后续路线。修仙题材的开源改编也采用“天赋开局—阶段推进—境界事件—结局”的结构，题材不同但机制相通。[《仙途·人生重启》项目说明](https://github.com/luul11/xiantu-life-restart)

**建议：**本产品无需让用户重新分配虚构属性点。将已有底账转成一张可确认的“开局画像”：年龄阶段、家庭结构、收入稳定性、月度结余、流动资金可支撑月数、债务负担、保障缺口、目标及目标期限、已采用的规划方案。用户只需补充对模拟至关重要的缺项；无法确认的字段标为“未知”，不按零处理。可选一项“人生倾向”（稳健、目标优先、保持现状）作为本局长期策略，但不得擅自更改真实账户。

### 2. 推进：一次点击是一个有意义的时间单位

原版代码按年龄逐步推进，每步抽取事件并记录该步属性；《打工人生模拟器》作者介绍的是一年一张事件卡、每年结算账单；《三十何立》的作者页面描述为按年龄的年度回合。[原版推进钩子](https://github.com/VickScarlet/remake/blob/main/packages/hooks/src/play.ts)、[《打工人生模拟器》开发者页面](https://www.taptap.cn/app/945557)、[《三十何立》开发者页面](https://store.steampowered.com/app/4552830/_/)

**建议：**默认“点击推进一年”，引擎仍按月计算。一个年度回合依次执行：月度常规收支与还款 → 已安排目标投入 → 本年适用的生活事件 → 事件财务影响 → 风险与目标检查 → 生成一张年度故事卡。若在一年中现金耗尽、目标到期或重大事件发生，立即停在该月，不把关键转折埋入年度汇总。提供“连播到下一个关键节点”，同时保留逐年点按；自动播放只替用户连续点击，不改变运算结果。

### 3. 事件：先判断能否发生，再决定发生什么

原版事件配置包含 `include`、`exclude`、权重、属性效果与后续分支；事件选择发生在按年龄划分的候选池里，满足条件后才参与抽取。[事件定义源码](https://github.com/VickScarlet/remake/blob/main/packages/data/src/event.types.ts)、[事件筛选及分支源码](https://github.com/VickScarlet/remake/blob/main/packages/core/src/event.ts)、[年龄事件池源码](https://github.com/VickScarlet/remake/blob/main/packages/data/src/age.types.ts)

**建议：**建立财务人生事件库，每个事件至少有：适用阶段、触发条件、互斥条件、冷却期、事件类别、强度档位、财务影响模板、可选决策、后续事件标签、叙事模板、证据来源。事件分四层：

| 层级 | 例子 | 处理方式 |
|---|---|---|
| 必然节点 | 目标到期、房贷还款、退休年龄到达 | 按已知日期触发，不随机 |
| 用户给定事件 | “两年后换工作”“计划生育” | 按用户确认参数触发 |
| 条件事件 | 现金储备不足时遭遇支出压力；有房贷时利率变化 | 只在条件满足时进入候选池 |
| 探索事件 | 收入下降、维修支出、教育开销 | 用明确的“虚构假设”强度抽取，绝不称为预测概率 |

要有事件链，例如“收入下降 → 缩减储蓄 → 现金储备变薄 → 目标需要延期”；不能每年从全库独立抽一张，导致前后矛盾。也要允许“平稳的一年”，但平稳年份仍展示资金和目标的可见进展。事件需要覆盖收入、家庭、住房、健康支出、照护、教育、市场与目标成本，避免只靠灾难制造戏剧性。

### 4. 状态：故事必须留下可见的后果

游戏中的属性变化会改变之后的事件资格和分支；职场类作品还把每年的收入、房租、生活费、房贷等结算成账单，并写入最终人生记录。[原版状态与事件源码](https://github.com/VickScarlet/remake/blob/main/packages/core/src/state.ts)、[《打工人生模拟器》开发者页面](https://www.taptap.cn/app/945557)

**建议：**模拟状态至少保存现金、其他资产、负债、月收入、月刚性支出、月可选支出、目标已准备金额、目标期限、家庭阶段、工作状态、保障状态、已发生事件和待续事件。每张事件卡展示“发生了什么 → 哪些数变了 → 为什么影响目标 → 后面留下什么”。这些变化须进入下一回合，不能只改变本期文案。

### 5. 选择、结局与重开

部分作品在关键节点提供选项，选项决定后续事件链；也有更接近用户所述的“只看命运发展”的自动路线。原版具备单局总结与重开记录；《浓缩的人生模拟器》开发者明确提到选择影响后续事件链；《三十何立》展示多种人生结局。[原版总结流程](https://github.com/VickScarlet/remake/blob/main/packages/hooks/src/play.ts)、[《浓缩的人生模拟器》开发者页面](https://store.steampowered.com/app/1577610/_/)、[《三十何立》开发者页面](https://store.steampowered.com/app/4552830/_/)

**建议：**默认“观察模式”：开局选长期策略后，只需点按推进。关键节点可出现“如果你愿意，也可以改选”的支线，但不强迫每年答题。结局不写“成功/失败人生”，而写可核对的财务结果：目标按期达成、目标延期、现金出现缺口、债务压力过高、目标调整后达成等。结局卡同时列出关键转折、最大资金缺口、最低现金储备、目标完成状态，以及可执行的规划调整。支持“同一开局重跑”和“固定相同事件，仅换方案”，帮助用户理解选择的影响。

## 三、现有实现与目标体验的差距

依据仓库的 [MVP PRD](../../FinAI_MVP_PRD.md)、[产品方案](../../FinAI_ProductSolution.md)、[现有界面](../src/components/execution-views.tsx) 与 [计算器](../src/domain/life-financial-simulation.ts)：

| 当前行为 | 对体验的影响 | 目标设计 |
|---|---|---|
| 开始前必须选单个突发事件并填写金额、月份 | 用户变成参数录入者 | 用已有画像直接开局，事件在推进中出现 |
| 时间线按月/季/半年显示一组财务数字 | 有时间，但没有连续的人生叙事 | 一年一张故事卡，关键月停顿，数字可展开 |
| 一局只允许一个重大事件 | 事件之间无法产生因果 | 多事件状态机、后续事件链、冷却和互斥 |
| 事件只改变收入或支出 | 人物状态与目标调整空间较窄 | 影响工作、家庭、住房、目标期限和现金储备等状态 |
| 目标投入固定持续，现金为负时仍照常投入 | 可能形成不可信的路径 | 定义现金不足时的暂停投入、动用储备、调整目标规则，并明示假设 |
| 结束时停在最后一期数字 | 缺少完整命运的收束 | 生成结局卡、转折回顾与可选的规划动作 |

还发现一个需在开发时核查的边界：界面把 `startMonth` 描述为“第几个月”，而计算器使用从零开始的循环索引判断 `index === startMonth`，可能使事件实际发生在晚一个月；新版应统一月份编号并用样例验收。[相关计算代码](../src/domain/life-financial-simulation.ts)

## 四、建议的产品流程

1. **选择开局。** 默认读取当前底账与已选规划，展示“你现在的财务画像”；可切换“匿名示例人生”体验玩法。开局卡明确数据日期、未知项和目标终点。
2. **选择模式。** 默认“观察人生”；另一入口为“指定情景”，沿用现有单事件压力测试，用于用户已经知道想测试什么的情况。
3. **点击推进。** 主按钮为“进入下一年”。页面顶部固定显示年份/年龄阶段、现金安全月数、目标进度；中央是本年故事卡；下方折叠展示年度账单和计算依据。
4. **遇到转折。** 事件卡先说故事，再给影响明细，例如“收入中断 3 个月 → 减少收入 ¥X → 储备从 Y 个月降到 Z 个月 → 购房目标可能延期 N 个月”。金额必须由计算器返回，文案不能临时编数字。
5. **暂停与回看。** 允许回看任意年份的已发生记录。改变开局、方案或事件假设时生成新分支，旧记录仍可查看，且标明“基于当时底账”。
6. **结局与比较。** 到目标日或预设模拟终点生成结局卡；用户可固定同一套事件重跑 Plan A/B/C，观察财务结局如何变化。比较时只改变方案，事件序列与强度保持相同。

### 一段示意体验（数字仅为界面占位，不作为计算结果）

> 2028 年 · 工作进入第 6 年  
> 你经历了收入中断。原本的购房储蓄计划暂停 3 个月。  
> 本年变化：收入减少〔计算值〕；可用现金从〔计算值〕降至〔计算值〕；购房目标预计需要调整〔计算值〕。  
> 你保留了紧急储备。下一年，收入恢复后的第一件事是重建安全垫。  
> **继续到 2029 年**　**查看这年账本**

## 五、机制与实现规格

**一次推进的顺序：**读取不可变的开局快照和本局种子 → 按月结算确定性现金流 → 触发必然/已确认节点 → 筛选满足条件的探索事件 → 按配置权重抽取 → 计算事件效果与后续标签 → 检查现金、债务、目标等边界 → 返回本回合账本、故事数据与下一回合状态。权重只用于生成可重复的虚构故事，不向用户表述为现实发生概率。

**事件数据示例（拟议格式）：**

```json
{
  "id": "career_income_gap_01",
  "stage": ["working"],
  "eligibility": ["has_employment_income"],
  "exclusions": ["income_gap_active"],
  "cooldownMonths": 36,
  "weight": 1,
  "assumption": { "incomeMultiplier": 0, "durationMonths": 3 },
  "effects": ["monthly_income", "cash_reserve", "goal_contribution"],
  "followUps": ["income_recovery", "goal_replan"],
  "narrativeTemplate": "这一年，你遇到了一段收入空窗期。"
}
```

**可复现性：**保存底账版本、已选方案版本、事件库版本、模拟起点、用户确认假设、随机种子和每步计算结果。相同输入与种子应得到相同事件和金额。真实底账更新后，历史局显示“旧版模拟”，不会被静默重算。

**AI 的边界：**AI 可将程序返回的结构化事件写成自然语言，或把用户口述映射成待确认的事件参数；事件资格、抽取、金额、目标状态和结局都由确定性规则处理。生成的故事需引用实际事件和计算字段，禁止自创疾病、裁员、收益率或家庭变故。财务健康不应只用净资产衡量；现金流控制、抵御冲击与目标进展也应作为结果维度。[CFPB 对财务福祉的定义](https://www.consumerfinance.gov/consumer-tools/educator-tools/financial-well-being-resources/)

**展示措辞：**全程写“假设发生”“在本次模拟中”“按当前已知数据与规则计算”；不写“你将在某年失业”“未来必然如此”。不展示没有依据的真实事件概率，也不把模拟收益当投资预测。现有产品方案已明确情景推演用于回答“如果发生会怎样”，而非预测事件概率。[产品方案](../../FinAI_ProductSolution.md)

## 六、最小可落地版本与验收

第一版先做一个完整可玩的闭环：当前画像开局、年度点按、确定性月度账本、约 20–30 张覆盖收入/住房/家庭/健康支出/目标的人工策划事件卡、3–5 条事件链、结局卡、固定种子重跑。事件数量是**研发规模建议**，不是调研事实。优先确保一个 10 年模拟能让用户看到多个互相关联的转折，并能解释每一笔金额变化。之后再扩充事件库、增加可选决策与更丰富的叙事。

验收建议：

- 从已有用户画像到第一张故事卡，正常路径无需重新输入财务数字；缺少关键字段时只追问该字段。
- 连续推进能在目标日结束；同种子同输入可复现，换方案比较时事件保持一致。
- 每个事件的资格、效果与后续分支都有可追溯记录；不会出现互斥事件同时发生或事件文案与账本不一致。
- 现金不足、目标到期和负债异常会在发生当月停顿并解释；不会让负现金无条件继续投资。
- 结局卡能回答“发生了什么、为什么变成这样、哪些调整会改变结果”，并明确这只是情景假设。
