# 产品一致性审阅

审阅日期：2026-09-17。依据产品方案 v2 和后续用户明确要求：单主 Agent、表单一次录入、自定义表头/类目、空金额为零、三个月行动、持续协助财富目标。

## 当前范围更新（2026-09-26）

“持续财富任务”及其专属会话接口、文字约束和工具编排已删除。首页目标对话保留；诊断、规划、推演和执行进度通过各自页面运行。历史会话与约束数据保留，无数据库删除迁移。

以下内容为2026-09-17起的历史审阅记录，不代表当前功能清单。其中财富任务绑定、文字约束、主 Agent 上下文和工具恢复已退出本次产品范围，相关旧测试数量也不是当前验收结果。当前能力以 README 为准。

## 历史结论

重构提供了会话和工具选择入口，但尚不能证明完整的持续财富管理闭环。此前将重构描述为完成的表述过于宽泛。以下缺口需要继续实施并逐项验收。

## 已修复并验证

- 行动不能使用原版本底账直接验证完成。需要新版本、同公式的历史基线和指标改善；缺少历史证据时保持待验证。
- 验证写入再次检查当前底账版本和行动状态，防止覆盖并发修改。
- 单轮工具上限由执行前检查强制执行，修正循环可能执行第五个工具的问题。
- 行动验证回归测试覆盖旧数据不通过、新数据改善通过。
- 保留所有历史行动，不再只显示最近一次生成结果；支持暂缓、拒绝和恢复，并标记过期底账与到期行动。状态变更有审计记录，旧底账建议不能直接接受。
- 批量底账保存要求 expectedRevision，在事务中检查版本，阻止旧页面覆盖新数据。
- 底账金额格式化改用 BigInt 和字符串，避免浮点转换损失分位；批量输入和编辑弹窗共用同一实现。
- 本轮验证：10个测试文件、27个测试通过，类型检查与 ESLint 通过。金额测试覆盖最大支持金额的显示/提交往返、千分符、空输入和非法输入；尚未完成全流程浏览器验收。
- 财富任务新增用户明确选择的 goalId；支持新建时绑定和已有任务修改，执行中禁止改绑，校验目标的工作区归属及删除状态。未绑定的 Agent 不得生成目标方案；后续压力测试、行动生成拒绝与绑定目标不符的所选方案。
- 目标绑定验证：29个测试通过，类型检查与 ESLint 通过；浏览器验证新建任务保存绑定、解除绑定后刷新仍保留。非首要目标规划和跨目标方案拒绝有服务端回归测试。数据库增量迁移已在本机应用。
- AI 诊断的三个月建议与诊断结果在同一事务入库，进入统一行动清单；记录诊断来源、步骤、前置条件、完成标准和改善验证要求，不再假造方案关联。诊断写入事务内再次验证底账版本。
- 同一底账下重复生成相同风险及标题的诊断行动，保留旧行动状态和期限；下一次诊断输入包含未完成行动。主 Agent 可读取行动详情。
- 诊断行动不按模型文本自动验证完成，保持 REQUIRES_REVIEW；新增服务测试覆盖入库、60日期限、接受、重复诊断保留状态、向模型提供旧行动和用户完成不自动验证。29个测试及生产构建通过，UI 详情呈现尚待浏览器验收。
- 暂缓、拒绝行动要求填写原因，在同一事务内保存独立反馈历史与状态变更；恢复行动不清除反馈。后续诊断和主 Agent 上下文接收标为 USER_CONFIRMED 的用户反馈，不把反馈当作财务改善证据。
- 反馈验收：30个测试、类型检查、ESLint 通过，数据库与 Prisma schema 无差异；桌面浏览器验证诊断行动详情、空原因禁用提交、保存暂缓状态及展开反馈历史。验收模拟行动已清理；移动端及完整用户旅程仍待验证。
- 底账资产、负债列标题支持编辑，并随底账在同一版本事务保存。旧工作区默认标题兼容；字段键及计算语义不随名称改变。新增表头校验与保存回归，32个测试、类型检查、ESLint 通过；表头浏览器及移动端验收待补。

- 底账草稿提升至页面状态，切换视图保留金额、类目和自定义表头；刷新前提醒，保存失败不清除草稿，旧版本草稿禁止覆盖新底账。生产预览桌面验收：输入 12,345.67 并修改表头，切换至行动计划后返回，内容保留；保存后版本从0更新至1，刷新后金额及表头仍保留。此前32项测试及生产构建通过。草稿仅保存在当前页面内存，不承诺刷新后恢复。
- 补充过期草稿属性编辑保护，避免已删除账户被传入编辑器；全局保存状态显示未保存底账草稿。此补充类型检查通过；移动端、并发页面及刷新拦截验收尚未完成。
- 财富任务新增独立的用户约束记录：支持必要边界/规划偏好、有效期、修改、撤销、重新确认、版本历史、乐观并发与审计事件。有效约束以 USER_CONFIRMED 单独传给主 Agent、诊断和规划解释，不依赖最近24条聊天，也不冒充底账事实；确定性候选尚未自动求解文本约束，模型必须说明冲突或未核验状态。
- 约束功能验证：35项测试、类型检查、ESLint与生产构建通过；桌面浏览器验证新增、修改、刷新恢复、撤销及三版确认历史，390px移动视口验证任务列表与对话不再重叠。
- 首页第一项功能已改为目标工作台：左侧包含目标想法入口、可滚动目标列表及编辑/删除操作，右侧通过同一 Agent 运行层逐步澄清目标、目标金额、目标日期和已准备金额；类型和优先级不再由用户填写。目标仅在四项完整且用户明确确认后写入。第二个及以上目标创建前要求一次性知情同意，目标仍分别保存并在分析时汇总。
- 目标工作台验证：38项测试、类型检查、ESLint及生产构建通过；桌面和390px移动视口布局已验收。兼容模型真实请求能够从模糊表述提取已确认信息、保留缺失字段并继续追问；兼容接口现显式传入JSON Schema，严格校验仍然生效。合成测试会话和目标已清理。
- 综合首页已加入当前财务状况记录：资产（收入）与负债（支出）并列展示，已有金额可直接修改，新增记录使用简化表单；支持文字和图片批量识别、预览校对后一次性写入。分期负债支持月供、期限、本息和、本金、利息及还款方式，并在服务端校验本息关系。
- 资产类型、流动性和风险等级由 `asset-classifier-v0` 根据名称自动补全，失败时使用可追踪的规则兜底。该分类提示词仍属于首版占位实现，需要通过真实用户资产名称样本持续评测和优化；模型推断不得作为用户确认事实展示。
- 综合首页新增“现状评估”：用户确认后并行生成四账户配置、风险诊断和三个月行动，全部结构化输出校验通过后才按同一底账版本保存。实际账户比例由程序计算，Agent只生成建议比例、评分与解释；底账变化后保留旧报告并标记过期。
- `four-account-allocation-v1` 已固化为服务端可部署 Prompt，不依赖运行机器上的本地 skill 文件。真实模型端到端验证通过，建议比例合计100%，四账户报告与风险行动在同一诊断结果中返回。

## 待完成

1. 会话与结构化 Goal 绑定已实现；仍需按目标查看历史方案，避免不同目标的最新方案互相遮挡。目前不匹配会明确阻止执行，不会静默执行其他目标方案。
2. 诊断行动已进入统一行动库，受阻原因已记录并提供后续分析；仍需历史方案可见和完整复盘。跨版本或改写标题的相似行动需显式调整/合并机制，当前只对同版本同风险同标题去重，不能视为完整行动复盘。
3. 用户约束已有独立、可确认、可修改、可撤销的结构化记录，并在聊天截断后持续传入模型。仍需把约束从“诊断/解释层提示”推进到确定性方案求解与冲突校验，当前候选方案只能明确标记尚未核验或由模型解释冲突。
4. 工具恢复需要持久运行标识、幂等性和失败步骤续跑；现有过期状态锁不能证明进程中断后可靠恢复。
5. 新资产属性不能作为已确认事实默默推定。草稿保护、列标题持久化、并发版本检查和精确输入金额格式化已实现；草稿切换与列标题桌面验收通过，移动端及并发草稿仍待验收。
6. 诊断已允许 AI 依据完整财务事实发现规则列表之外的新问题；行动仍必须引用本次诊断风险，金额仍必须来自程序确认的可调整金额。后续需通过评测集持续验证新风险证据是否忠于输入。
7. 复盘需要比较历史与当前证据，并将到期、过期和受阻行动呈现给用户。
8. 完整用户旅程验证需要覆盖：填写底账、建立目标、约束确认、比较方案、行动执行、新底账验证、重新访问继续任务。
9. 综合首页已完成人生目标及资产负债记录区域；后续功能应继续在同一首页按产品定义整合，不新增重复录入入口。
10. 图片识别依赖模型平台实时提供的视觉模型；上线前需固定经验证的模型版本，并补充供应商可用性、识别准确率与敏感信息处理评测。

## 产品边界

- 保留单主 Agent 与确定性计算工具，不自动交易。
- 后续用户要求优先于旧方案中的“本月行动”和“可投资资产”术语。
- 公开产品候选搜索、投资收益和波动指标尚缺数据来源；不能描述为已实现，也不能用编造数据填补。
- 当前匿名工作区不能等同于正式账户认证；部署说明必须准确反映这一现状。
