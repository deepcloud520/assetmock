# 五 Agent 场景验收与展示样例

日期：2026-10-04  
用途：重构完成后的实际测试与展示脚本；不定义产品适用范围或通用技术契约。

架构依据：[五 Agent 重构方案](five-agent-refactor-v1.md)。

## 1. 展示样例：买车

用户输入：“我想明年买车，还没想好预算，希望生活支出不要受太大影响。”

1. 总管家理解目标并确定讨论作用域，目标管家澄清时间、必要性和可接受取舍。
2. 预算未知时继续保存决策草稿，不强迫用户先填完整目标表单。
3. 收支管家核对生活预算与可投入金额；保险管家检查已确认保费承诺；投资管家核对资金可用时间及其他用途占用。专业参与根据实际缺失项选择。
4. 目标管家通过通用决策工具选择已支持的计算能力，比较资金安排与生活影响。可用贷款报价时测试分期计算；没有报价时只能带假设试算。
5. 用户确认保护资金或其他红线后，程序重新检查候选；违反或无法判断的候选不能直接采纳。
6. 用户选择方案，在结构化界面确认；系统保存生效版本、资金安排及行动，目标管家解释下一步。
7. 用户下次核对奖金延期或收入下降，系统保留原方案，展示影响及调整草稿；确认后生成新版本。
8. 用户完成目标后确认实际费用及后续承诺，停止已结束的筹资任务，继续维护实际持续支出。

演示证据包括：会话恢复、真实专业子运行与工具步骤、资料版本、计算来源、确认记录、资金预留、旧方案与新方案差异。

## 2. 通用性验收

另以“建立应急储备”和“准备一笔有期限的个人支出”验证同一目标、决策、现金流、约束与方案接口。数据结构和工具名称不因样例变化而改变；没有外部融资需求时不询问贷款报价，没有复杂持续费用时不加载专项输入卡。

对于当前不能可靠计算的目标，必须明确返回能力不足和可完成的部分，不以语言生成虚构计算结果。

先使用合成资料验证工程闭环，再经用户授权用于真实案例。工程验收通过不等于完成用户需求验证。
