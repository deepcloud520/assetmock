# AI 资产管家需求补充：目标对话、分阶段补问与决策记忆

版本：讨论补充 v1.0  
日期：2026-10-03  
状态：后续小优化的规划依据；本文新增要求不代表已实现或已验证。

## 1. 与现有 MVP 的关系

本文补充《AI 资产管家 MVP 产品认知与目标规划框架》和《AI 资产管家 MVP：买车决策与月度维护》，用于下一次小范围优化。

现有工程说明见 [买车决策与月度维护 MVP](./car-purchase-mvp.md)。该说明已列出买车草稿、计算、采纳、复盘及对话等能力。正式排期前，应核对当时的代码和页面，复用已有能力，避免重复建设。本文不重新证明其测试结果。

本次优化围绕一个问题：

> 理财小白能否从首页说出一个目标，在尽量少重复填写的情况下理解取舍、选择方案，并让系统在后续维护中记住已经确认的决定？

### 已确认的产品前提

1. 服务理财小白；首轮优化仍围绕真实买车需求开展。
2. 预算允许未知，也允许在比较中调整。
3. 产品原本就需要推荐不同影响程度的预算方案。本次补充要求其在实现中清晰呈现，并区分预算上限、推荐方案与用户选择。
4. 资产和负债作为财富底账继续保留现有结构、录入与管理方式。目标对话复用这些事实，不为本次优化重做底账。
5. 复用财富总览“目标”区域的 AI 对话入口，扩展其职责。
6. 用户不需要常规填写“选择理由”。系统从明确表达、确认事件和选择行为中保留证据；理由不明时允许保持未知。
7. 重要计划变化及财务数据写入继续使用既有确认流程。

## 2. 本次小优化的范围

### 纳入首轮

- 首页目标对话可继续补问本次决策所需财务信息，并承接方案比较和确认。
- 读取已有底账，按判断缺口分阶段追问，保留断点并支持继续。
- 对话中使用资料确认卡、资金使用卡和方案对比，减少金额的重复文字输入。
- 保存明确表达、选择事件及必要的待核实推断，并记录来源和适用范围。
- 在个人画像中增加简洁的“规划偏好与约束”查看区。
- 按工作流阶段选择上下文，支持纠正、失效和重新核实。

### 后续再考虑

- 扩展到买房、养老等其他目标的完整决策流程。
- 建设四套分管家的独立聊天入口。
- 通用长期记忆平台、向量检索、复杂偏好学习或自动人格判断。
- 根据单次选择自动修改投资风险等级。
- 为收集信息新增账户直连、交易执行或完整保险分析。
- 重建现有计算、采纳和复盘模块。

## 3. 入口与连续交互

### 3.1 对话职责升级

原有目标对话侧重澄清名称、金额、时间等信息。本次将其扩展为一次目标决策的连续交互：

> 表达想法 → 读取底账 → 补问关键缺口 → 初步判断 → 比较取舍 → 确认计划 → 后续维护。

首版只让买车目标进入扩展流程；其他目标沿用已有流程。无法明确识别目标类型时，先澄清，不自动归入买车。

用户可以在同一会话中继续，也可以打开现有买车详情页。两种入口共享同一份决策草稿、当前阶段和生效方案，不创建两份互不关联的目标。

目标尚未澄清到确定金额时保留草稿。正式目标及方案的创建时机继续遵循买车 MVP 的采纳流程。

### 3.2 对话与结构化交互配合

- AI负责理解表达、说明结果和自然追问。
- 数字、日期、资金来源和确认操作通过轻量卡片辅助核对。
- 候选方案及数值沿用确定性计算结果。
- 每轮默认最多追问两个相关问题，用户可主动一次补充多项信息。
- 已取得的信息不重复询问；发生依赖变化或实质冲突时再核实。
- 暂停后恢复原草稿，不要求用户重新讲述目标或重填底账。

对话页面应能回答“目前知道什么、还缺什么、补充后能得到什么”。不以完成整张资料表作为用户首次获得价值的统一前提。

## 4. 在不改底账的前提下分阶段补问

### 4.1 新增决策资料层

资产、负债底账提供当前财务事实；决策资料层保存这些事实在本次目标中的用途、边界、假设和确认情况。

例如，底账记录某笔存款为 8 万元，用户表示本次买车最多使用 5 万元：

- 底账继续记录 8 万元。
- 决策资料关联该资产 ID，记录本次可使用上限 5 万元。
- 未使用部分仍属于真实资产。
- 方案采纳时沿用既有资金预留机制。

若用户说实际余额已经变化，对话提示其核对并进入既有底账更新流程；不把计划中的可用金额直接覆盖为真实余额。

### 4.2 收集顺序

| 阶段 | 复用或补充的信息 | 交付给用户的结果 |
| --- | --- | --- |
| 理解目标 | 用途、期望时间、预算意向；预算可留空 | 确认本次要解决的问题 |
| 初步判断 | 已有底账、可用资金及持续收支的关键缺口 | 当前可判断的结果、尚不能确定的部分 |
| 比较取舍 | 会影响方案的资金边界、费用、时间弹性和偏好 | 不同预算、时间或付款方式的影响 |
| 确认采纳 | 所选方案实际依赖的信息和假设 | 一份可核对、可执行的方案 |
| 月度维护 | 实际变化及与原方案有关的缺口 | 继续执行，或需要调整的明确原因 |

### 4.3 下一步问什么

采用“工作流判断缺口，AI组织表达”的方式：

1. 检查已有资料及来源、确认状态、是否仍然有效。
2. 找出影响当前计算或下一步选择的缺口。
3. 优先问会改变资金可用性、可行性或方案取舍的问题。
4. 将用户明确提供的信息保存到对应字段，展示关键数字供核对。
5. 取得新信息后更新判断，再决定是否继续追问。

首轮以规则和现有计算模块提供缺口清单即可，不要求实现通用信息价值优化算法。

具体规则：

- 用户仅考虑全款时，不要求填写贷款报价。
- 某项资产不参与任何当前候选方案时，不提前索取全部赎回细节。
- 保障资料按对本次决策的影响补充；未知保费会影响现金流时必须核实，未核实保障内容则限制保障结论。
- 缺失值不解释为零，未确认的默认值不当作事实。
- 有足够依据时可先显示局部结果或带明确假设的试算；无法形成可信范围时，说明缺口，不强行给预算数字。
- 正式采纳的关键校验继续保留，不能用“分阶段体验”绕过。

### 4.4 底账发生变化

决策资料记录其依赖的资产、负债及资料版本。余额、归属或相关负债变化后：

- 读取最新底账参与计算。
- 使受影响的计算结果过期，并重新检查相关资金边界。
- 保留未受影响的已确认资料和偏好。
- 旧快照只用于解释历史决定，不作为当前可用余额。
- 不通过对话中的旧金额覆盖较新的底账。

## 5. 预算与方案表达

| 概念 | 含义 | 展示要求 |
| --- | --- | --- |
| 预算上限 | 在所列假设和约束下可承受的边界 | 标明约束和依赖，不直接称为适合买的价格 |
| 推荐方案 | 结合目标、已确认偏好及财务影响给出的选择 | 说明与用户需求的联系及主要代价 |
| 用户选择 | 用户理解后果后接受的具体方案 | 保存方案版本、已接受取舍和确认事件 |

不同影响程度应通过具体后果表达：剩余可用资金、月度余量、应急储备、其他目标、长期资产和需要执行的消费调整。

当期望预算可行时，仍可展示有实际取舍差异的其他方案；相同金额、时间、资金来源和影响的重复方案无需凑数。

用户接受消费削减，只表示接受这项计划。尚未执行的削减与实际已经实现的支出变化分别记录，并在复盘中核对；不得重复计入节省金额。

## 6. 选择理由的获取与使用

### 6.1 不增加常规理由填写

不在采纳后强制用户写“为什么选择”。优先使用已有对话中的明确表达，以及方案确认事件。

需要区分：

- **明确表达：** “本次买车不想动这笔基金。”
- **客观选择：** 用户采用延期方案，并确认其资金安排。
- **待验证推断：** 用户可能更重视保留长期投资。

选择事件可以证明用户选了什么，以及明确展示并确认了哪些取舍。它不能单独证明深层动机，也不能自动成为长期偏好。

### 6.2 何时确认

- 用户已明确表达的信息，提取后在相应资料卡或采纳摘要中呈现，避免反复确认。
- 推断只影响解释顺序时，可保留为待核实理解，不增加独立确认步骤。
- 推断将影响硬约束、排除可行方案或修改长期画像时，必须取得明确确认。
- 下一次出现实质冲突时，以具体取舍问题核实，例如“继续避免贷款，还是优先保留购车时间？”
- 普通的“确认方案”只确认展示的方案内容；未展示的推断或长期规则不能随之自动生效。

### 6.3 准确性要求

不承诺模型对隐含动机具有固定高准确率。系统应允许不生成推断，并以证据约束使用范围。

首轮优先做好明确表达的提取、来源关联和纠错。无需为每次选择生成推测，也不使用模型自报的置信度直接授予约束权限。

保存“可核对的证据、结论与适用条件”，不要求保存模型内部思考全文。

## 7. 存储与个人画像

### 7.1 逻辑上分为三类记录

| 记录 | 主要内容 | 更新原则 |
| --- | --- | --- |
| 决策资料 | 本次目标信息、资产使用边界、费用假设、确认状态、依赖版本 | 跟随草稿及用户核对更新 |
| 决定记录 | 候选方案、所选方案、当时资料版本、已接受取舍、确认事件 | 已采纳历史保持可追溯 |
| 偏好与理解 | 明确偏好、确认规则、待核实推断、证据和适用范围 | 可纠正、失效、被新记录替代 |

复用当前买车草稿、方案版本、复盘和对话存储。决定记录可通过方案快照和选择事件补充，不先建立重复的方案系统。

### 7.2 偏好与理解的最小字段

| 字段 | 用途 |
| --- | --- |
| 内容 | 一条具体、可理解的偏好、约束或推断 |
| 依据类型 | 用户明确表达／观察到的选择／AI推断 |
| 来源引用 | 消息、选择事件或确认事件 ID；必要的短证据摘录 |
| 适用范围 | 当前决策、目标，或用户明确确认的全局范围 |
| 使用性质 | 软偏好或已确认硬约束 |
| 状态 | 待核实、有效、待复核、被替代、已删除 |
| 依赖与复核条件 | 相关目标、资产或条件，以及何种变化需要重新核实 |
| 时间与版本 | 创建、更新、确认时间；AI生成时保留模型及提示词版本 |

“有明确证据”和“属于硬约束”是两个不同维度。“不太想贷款”可作为明确软偏好；是否完全排除贷款，需要结合用户表达及本次确认判断。

默认作用域为当前目标。只有用户明确赋予长期、跨目标含义时才进入全局范围；系统不得自行升级。

### 7.3 个人画像的呈现

在现有个人画像中增加轻量的“规划偏好与约束”区域，分组显示：

- 已确认、可复用的偏好。
- 当前目标的约束，并明确标注目标名称。
- 待核实理解，折叠显示且不强制清空。

每条记录支持查看依据、纠正、删除；需要时支持确认适用范围。展示可以统一，底层仍保留不同记录的来源和作用域。

删除或被替代的记录立即退出后续上下文。历史方案保留当时已确认的依据供追溯，不能继续以旧偏好约束新决策。历史财务证据不通过普通运行日志输出。

## 8. 什么时候加入上下文

采用按任务筛选的上下文组装，首轮使用结构化查询即可。

| 工作流阶段 | 加入的内容 | 排除的内容 |
| --- | --- | --- |
| 新目标澄清 | 当前表达、已确认的全局规则、明确相关的偏好 | 其他目标的一次性取舍、无关历史聊天 |
| 资金与可行性计算 | 最新财务事实、有效且确认的硬约束、当前资金占用 | AI动机推断、旧余额、尚未确认的假设值作为事实 |
| 候选方案与解释 | 当前目标软偏好、确认约束、相关选择记录；确有帮助时加入标记清楚的待核实推断 | 无关画像及无法追溯来源的总结 |
| 方案采纳 | 本次明确展示的方案、取舍、约束和依赖条件 | 未向用户展示的隐含规则 |
| 月度复盘 | 生效方案、当时接受的取舍、最新实际情况 | 旧快照替代现值、其他目标无关的选择理由 |
| 调整方案 | 与本次变化有关的约束、偏好和证据 | 已失效、被替代、已删除的理解 |

补充规则：

1. 先按工作区、目标、状态和依赖筛选，再让AI解释，不先把所有历史交给模型自由挑选。
2. 当前明确表达与历史记录冲突时，以当前表达形成候选更新，并使相关旧记录待复核；已生效方案仍须通过确认流程修改。
3. 收入或家庭责任变化不自动抹除所有偏好。只有与变化有关、或已导致实质冲突的内容需要重新核实。
4. 确定性金额计算不依赖AI猜测；待核实推断不得直接改变金额、占款、硬约束或用户风险等级。
5. 资料不全、证据不足、上下文冲突时，回到具体问题或显示不确定，不生成虚假的确定性理由。

## 9. 实施路线

本次按依赖顺序实施，作为一次小优化拆分验收。先保证连续交互和显式证据，再增加有限推断。

### 第一步：核对现状与统一决策入口

工作内容：

- 核对首页目标对话、买车草稿与详情入口之间的关系。
- 将买车意图关联到同一决策记录，保留现有未完成对话和草稿的恢复路径。
- 明确当前阶段及下一步；其他目标保持原流程。

交付与验收：从首页表达买车意图后可继续补资料、查看方案；刷新或切换页面不会创建重复决策，也不会丢失已填资料。

### 第二步：按缺口补问，并嵌入确认卡

工作内容：

- 从底账读取已有事实，在决策资料中保存新增边界、假设和确认状态。
- 将缺口清单划分为当前必需、采纳前必需及暂不相关。
- 让AI围绕优先缺口追问；使用卡片确认资金可用范围、金额和日期。
- 将局部结果、试算与可采纳方案明确区分。

交付与验收：用户不需要重新填写资产负债；预算未知可以继续；全款路径不被贷款资料阻塞；关键未知不会被当作零或正式事实。

### 第三步：保存明确偏好与选择证据

工作内容：

- 先实现明确表达的结构化提取及来源关联。
- 采纳摘要列出用户接受的实际取舍，关联不可变方案版本。
- 增加最小偏好记录及查看、纠正、删除能力。
- 个人画像呈现已确认偏好和当前目标约束，不增加理由填写表单。

交付与验收：能够解释某条偏好来自哪句话；选择延期不能被自动解释为长期厌恶负债；修改偏好不会无确认地改写生效方案。

### 第四步：按阶段组装上下文，接入复盘

工作内容：

- 实现上下文筛选与来源标记。
- 复盘调用生效方案及相关取舍，当前金额始终读取最新事实。
- 对冲突、过期和纠正后的记录进行正确处理。
- 增加有限、可放弃的推断能力，仅用于解释和下一次核实。

交付与验收：数据变化时只核实受影响内容；已删除偏好不会再次进入推荐；推断无法绕过确认成为硬约束。

### 第五步：理财小白试用与收敛

工作内容：

- 选取少量正在认真考虑买车的理财小白，观察完整使用过程。
- 记录重复提问、难以理解的字段、错误提取、错误动机推断及用户纠正。
- 根据结果删减问题与界面元素，再决定是否扩大自动推断范围。

交付与验收：用户能够复述所选方案的主要资金来源与代价，并在恢复会话或复盘时感受到系统记住了既有决定。

首轮不以推断准确率的主观评分作为发布依据；先验证无证据的推断不能触发实际约束和计划变化。

## 10. 验收场景

| 场景 | 预期行为 |
| --- | --- |
| 首页输入“明年想买车，还不知道预算” | 创建或继续买车草稿，读取底账，不强制先填目标金额 |
| 底账已有存款及负债 | 直接复用，补问用途或可用时间；不重复录入余额 |
| 8万元存款只愿用于买车5万元 | 保存目标使用边界；真实余额仍为8万元 |
| 用户只考虑全款 | 不要求贷款报价，也不阻塞全款方案比较 |
| 某项费用未知 | 说明影响，追问或进行标明假设的试算；不自动按零正式采纳 |
| 用户说“本次不想动基金” | 保存本次目标偏好及来源，不自动成为永久投资原则 |
| 用户选了便宜的全款方案 | 保存选择与已接受影响，不直接推断其厌恶负债 |
| 用户确认某一方案 | 仅采纳展示且确认的内容，不暗中确认长期画像 |
| 用户否认或删除一条理解 | 后续上下文立即停用，历史方案仍可追溯 |
| 新目标与旧目标用途不同 | 不自动套用旧目标的一次性取舍 |
| 底账变化、原约束受影响 | 使用新数据重算，只重新核实相关约束 |
| 消费削减已反映在实际支出中 | 复盘不再重复加算节省金额 |
| AI超时或输出不合法 | 保留草稿、事实和计算结果，通过规则缺口和确认卡继续 |
| 刷新或从详情页返回首页 | 恢复同一决策、当前阶段与对应记录 |

产品观察指标包括：首次得到有用判断的时间、重复填写次数、重复追问次数、用户对取舍的理解、提取纠正情况、无证据偏好写入情况，以及复盘时是否重新解释相同背景。

工程验收应覆盖状态流转、工作区隔离、来源引用、约束权限、资料版本变化和记忆停用，并保留既有金额计算、采纳及复盘的回归测试。首轮试用后再制定转化率、时长等量化目标，避免预先假定成功标准已经得到用户验证。

## 11. 排期前需要锁定的细节

本文件明确需求边界，正式实施方案还需结合当时实现确认：

- 首页对话与买车详情如何共用状态，以及已有会话的迁移或关联方式。
- 现有草稿、方案快照可直接复用的字段，偏好记录最小存储扩展。
- 各阶段准确的必需字段与缺失时可展示的结果。
- 个人画像区域和对话确认卡的具体交互稿。

这些属于后续小优化的设计与技术细化，不影响本文已确认的原则：复用底账、连续交互、按需补问、证据可追溯、推断可修正，以及重要变化由用户确认。
