## 1. 使用方式与优先级

本清单用于后续排期，不表示任务已启动或已获得外部服务采购授权。全部复选框初始未完成，完成时补充实现版本、验证日期和证据链接。

- **P0 / MVP 前置**：影响首版真实性、一致性及恢复能力，必须在 MVP 完成前解决。
- **P1 / 二期优先**：在首版验收通过后，优先评估和实施的增强能力。
- **P2 / 后续候选**：依据试用反馈决定，不自动进入二期承诺。

首版边界保持：用户手动交易；沪深主板、创业板、科创板；免费行情优先；默认初始资金 10 万元；当日限价单；模拟与真实资产隔离；遵循真实交易时间。历史回放、AI 自动交易属于本清单的后续增强。

## 2. MVP 前置验证清单

以下事项不是可延期的高级功能。与技术方案 B0—B4、PRD A01—A15 对齐。

- [ ] **M00｜核实免费行情的实际时效（P0）**  
  用户价值：显示可解释的数据时间，避免用旧价格交易。前置：真实交易日、两种候选来源和三个板块正常证券。验收：按技术方案 B0 留存上午/下午样本、失败率、源时间年龄、字段完整性及频率结论；3—5 秒仅为试验起点，休市约 250 ms 请求结果不算实时性验收。

- [ ] **M01｜核实市场规则、费用及资料使用条件（P0）**  
  用户价值：知道哪些股票可交易、为何拒单、费用如何产生。前置：交易所及来源文档。验收：形成按板块、生效日和来源版本管理的规则表；明确特殊证券排除范围、时段、数量、价格、可卖日、费用及数据使用范围，未知字段可阻断交易。

- [ ] **M02｜验证账本、冻结和订单一致性（P0）**  
  用户价值：资金不会重复扣减、重复消费或超卖。前置：账户与交易模型。验收：重复提交、部分成交、撤单竞争、最低佣金、卖出尾差及数据库跨空间引用测试通过，现金和持仓可由事实重建。

- [ ] **M03｜交付公司行为检测与最低处理机制（P0）**  
  用户价值：分红送转不会变成虚假亏损。前置：事件来源及覆盖核对。验收：已知事件及未知覆盖均可触发暂停；人工核对与受支持调整幂等；不支持事件保持收益不完整，原成交记录不被覆盖。完整自动处理属于 O01。

- [ ] **M04｜验证服务端撮合和重启恢复（P0）**  
  用户价值：浏览器关闭仍能处理挂单，停机后结果可解释。前置：独立 worker、租约、持久化订单。验收：双 worker、旧租约、停机跨日、成交后响应丢失及过期单处理通过；没有补造离线成交。全天候托管属于 O02。

- [ ] **M05｜完成数据隔离、备份与删除闭环（P0）**  
  用户价值：模拟结果不污染真实规划，历史可恢复、个人数据可清除。前置：新增业务表、数据管理接入、跨进程维护控制。验收：A12、A15 通过，备份在隔离环境恢复可对账；删除覆盖笔记、快照、派生文本、缓存及受管理备份。

- [ ] **M06｜完成三板块手动交易验收（P0）**  
  用户价值：完成一次能看懂、可持续复盘的交易。前置：M00—M05。验收：PRD A01—A15 均有结果与证据；确定性测试和真实行情检查分别记录；原有真实资产、产品筛选、对话及目标流程回归通过。

## 3. AI 自动模拟交易

AI 介入的后续方向是用户授权下的自动模拟交易。首版预留统一服务接口，二期逐项开放；任何 AI 能力失败都不能绕过账本或交易规则。

- [ ] **AI01｜明确自动交易授权与独立资金范围（P1）**  
  用户价值：清楚 AI 能动用哪份模拟资金、交易哪些证券。前置：M06、账户隔离。验收：授权记录包含账户、股票范围、资金上限、期限及版本；撤销后禁止新订单；不允许将真实财务账户自动映射成可交易资金。

- [ ] **AI02｜策略配置与版本管理（P1）**  
  用户价值：了解交易依据，能比较修改前后的行为。前置：AI01。验收：保存策略目标、使用数据、持有周期、约束、触发条件及版本；策略变化不重写旧交易理由；自动执行前用户能审阅配置。

- [ ] **AI03｜接入投资 Agent 工具与权限（P1）**  
  用户价值：让投资管家执行已授权的模拟操作。前置：AI01、AI02、统一交易服务。验收：查询、预览、提交、撤单通过服务校验，记录 run、策略与授权版本；其他 Agent 无授权不能下单；模型不能直接修改余额、费用或交易规则。

- [ ] **AI04｜风险限额与停止开关（P1）**  
  用户价值：限制连续错误决策造成的模拟损失。前置：AI01、行情质量门槛。验收：单笔金额、单股仓位、总仓位、频率、回撤/亏损限制均由程序校验；停止后不再创建订单，既有挂单的保留或撤销由明确策略决定，并验证停机重启后不会自行恢复授权。

- [ ] **AI05｜自动运行调度与失败恢复（P1）**  
  用户价值：任务能按计划持续运行，同时避免重复下单。前置：AI03、AI04。验收：区分策略运行与撮合 worker；模型超时、配额不足、无效输出、数据缺失、重复触发均有确定处理，外部调用不进入数据库写事务；每个触发可追溯到唯一决策结果。

- [ ] **AI06｜逐单决策证据与自动交易试验（P1）**  
  用户价值：知道 AI 为什么买卖，能核实其行为。前置：AI02—AI05。验收：每笔订单保留当时事实、工具结果、原始理由、规则检查及成交差异；回放不读取未来数据；受控样例通过后才允许持续运行，收益高低不替代行为正确性验收。

## 4. 交易能力增强

- [ ] **T01｜市价及条件单（P2）**  
  用户价值：支持更灵活的下单习惯。前置：限价闭环稳定、对应板块规则核实。验收：逐类型定义市价保护、触发价来源、跳空行为、部分成交、过期和重启恢复；不把止损触发等同于一定按止损价成交。

- [ ] **T02｜更细致的成交与流动性模型（P2）**  
  用户价值：减少简化盘口导致的乐观结果。前置：具备合适的盘口/成交数据及使用权限。验收：加入多档深度、成交量约束或冲击模型，保留模型版本；与首版同订单对照报告差异，不宣称免费快照可还原真实排队。

- [ ] **T03｜集合竞价、盘后与特殊证券（P2）**  
  用户价值：覆盖首版不支持的 A 股操作。前置：状态、报价、适用规则及公司行为可靠。验收：分别实现开收盘竞价、科创板盘后机制或选定特殊证券，独立开关与测试；不能统一放开所有特殊状态。

- [ ] **T04｜更多市场与品种（P2）**  
  用户价值：拓展投资学习范围。前置：单独需求确认及数据评估。验收：每个市场/品种分别处理币种、日历、费用、最小单位、可卖规则和收益；北交所、ETF、可转债、港美股分别立项。真实券商交易不因本项自动获得授权。

- [ ] **T05｜多策略账户与模拟入金管理（P2）**  
  用户价值：公平比较多个策略或不同资金安排。前置：隔离账户、AI01 和可靠收益指标。验收：策略资金不重复占用；转入转出形成明确流水，收益采用能排除资金流入影响的口径；重置不掩盖历史结果。

## 5. 研究与训练

- [ ] **R01｜独立历史回放训练（P1）**  
  用户价值：休市时也能练习和展示交易。前置：历史数据和公司行为可用、交易引擎可注入时钟。验收：历史账户与跟随市场账户隔离；只有已推进到的历史资料可见；暂停、快进、重启可重复，界面明确回放日期。

- [ ] **R02｜策略回测与共享交易规则（P1）**  
  用户价值：在持续模拟前检查策略行为。前置：R01、AI02。验收：回测和模拟盘共享费用、可卖规则及成交政策；对同样输入给出可解释一致结果，禁止用当根最终收盘信号回填此前成交。

- [ ] **R03｜样本外验证与实验记录（P1）**  
  用户价值：区分一次偶然盈利和可重复的策略表现。前置：R02。验收：训练、调参、样本外区间及选股池有版本；保存失败实验、存活偏差和数据限制；滚动验证不回看未来资料。

- [ ] **R04｜评估外部研究框架（P2）**  
  用户价值：在需求成熟后减少复杂研究功能的重复开发。前置：R02 的能力缺口清单。验收：重新评估 vn.py、a-share-quant-sim、RQAlpha 的维护、许可、成本及可替换性，通过隔离原型比较后再决定，不以 README 功能声明代替验收。

## 6. 行情服务

- [ ] **D01｜付费行情与使用授权（P1）**  
  用户价值：获得更明确的数据覆盖、使用范围与支持。前置：M00 的缺口证据、预算确认。验收：对比覆盖、时效、配额、保存与展示权限及总成本；明确采购选择后再接入，能替换适配器而不迁移交易事实。

- [ ] **D02｜持续数据质量监测（P1）**  
  用户价值：接口变化时及时发现并停止错误成交。前置：首版来源健康记录。验收：监测延迟、字段漂移、缺失证券、时钟偏差和异常价格，分开标记市场休市、停牌及技术故障；告警与撮合暂停均可演练。

- [ ] **D03｜多源核对与可解释切换（P1）**  
  用户价值：减少单一来源故障造成的中断。前置：两个来源各自通过契约与权限验证。验收：价格与时间差异超阈值时暂停而非盲选；每个成交引用唯一来源快照；来源切换不能回退时间、重放盘口额度或重写历史报价。

## 7. 收益与复盘

- [ ] **P01｜基准比较与回撤（P1）**  
  用户价值：理解盈利是否只是随市场上涨，并认识波动。前置：可靠估值序列与基准数据。验收：区间、币种、交易日及收益口径一致；最大回撤与缺失点处理可复算；数据不足时不填造指标。

- [ ] **P02｜收益归因与交易行为分析（P2）**  
  用户价值：理解个股、仓位、择时与费用对结果的影响。前置：P01、完整交易与公司行为账本。验收：分项归因能与总收益对账；换手、持有时长等指标口径明确；不会从交易行为自动推断用户动机。

- [ ] **P03｜AI 复盘与后续行动（P1）**  
  用户价值：把交易事实整理成可学习的反馈。前置：可查询的历史事实、原始理由及质量标记。验收：结论引用具体交易和资料时间，区分事实与推测；模型失败仍可看完整记录；建议不直接改变策略授权或自动下单。

## 8. 持续运营

- [ ] **O01｜公司行为自动处理（P1）**  
  用户价值：降低长期持仓的人工核对成本。前置：M03、可靠事件数据及具体税务口径。验收：按登记日权益和支付/生效日处理分红、送转及支持事件；迟到更正可冲正；重复数据不重复入账；复杂事件仍能转人工。

- [ ] **O02｜全天候托管与独立监控（P1）**  
  用户价值：本机关闭后仍能按约定运行。前置：受控 MVP 验收、部署及账户权限设计。验收：进程守护、密钥管理、调度、备份、监控独立于浏览器和用户访问，重启或扩容不会双重撮合；本项增强首版 worker，不取代首版服务端运行要求。

- [ ] **O03｜自动对账与故障演练（P1）**  
  用户价值：长期运行后仍能发现并恢复异常。前置：M02、M04、M05。验收：定期重建现金、成本、数量和冻结；偏差自动暂停受影响账户并保留证据；模拟磁盘、网络、进程及备份故障，恢复后不重复下单。

- [ ] **O04｜多人公开服务发布门槛（P2）**  
  用户价值：在明确账户隔离和服务边界下共享产品。前置：O02、数据使用授权及独立发布决策。验收：身份认证、细粒度授权、资源配额、跨工作区隔离和数据删除恢复验证通过；公开展示数据的权限有依据。首版本地工作区 ID 不能直接充当公开授权。

## 9. 建议推进顺序

1. 先完成 M00—M06，获得可对账的手动模拟盘及稳定性证据。
2. 若下一目标是 AI 自动交易，依次完成 AI01/AI02 → AI03/AI04 → AI05/AI06；O01、D02 支撑持续运行。
3. R01—R03 建立训练和验证环境，帮助审核策略；历史回放和跟随市场运行的绩效分别展示。
4. 依据真实试用问题选择付费源、更多订单、归因和市场扩展，不以功能数量作为阶段完成标准。
